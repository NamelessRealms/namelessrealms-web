## 目標

白話：這個 repo 同時養著兩份依賴鎖定檔——`yarn.lock`（yarn 用）與
`package-lock.json`（npm 用）。實際上本地與 Docker 建置**都只走 yarn**，
npm 那份是舊時代殘留：留著它，哪天有人手滑跑 `npm install` 就會讓兩份分岔，
之後「裝到的版本」取決於用哪個工具，可重現性就毀了。
本任務把 npm 那份 lock **連檔案帶版控一起刪掉**、在 `.gitignore` 補擋防它回來，
並順手清掉 Dockerfile deps 階段裡**永遠走不到**的 `npm ci` / `npm install` 死碼分支。

做完的樣子：repo 只剩 `yarn.lock` 一份鎖定檔（版控、硬碟皆然）；
`.gitignore` 會擋住再生成的 `package-lock.json`；Dockerfile deps 階段
無條件 `yarn install --frozen-lockfile`，全檔再無 `package-lock.json` / `npm ci` 字樣；
`yarn install --frozen-lockfile`、`yarn build`、`docker build` 三者實跑皆過。


- COPY 由 `yarn.lock* package-lock.json*` 收斂為精確的 `yarn.lock`：

## 風險

| 風險 | 等級 | 緩解 |
|---|---|---|
| `.gitignore` 規則寫太寬（如 `*lock*`）誤擋 `yarn.lock`，破壞建置可重現性 | **高** | 本包已給逐字終態（精確檔名）+ 驗收第 4 條獨立取證不命中 |
| 手滑跑 `npm install` 重新生成 `package-lock.json` | 中 | 硬約束明禁 + `.gitignore` 新規則兜底 + 驗收第 1、2 條 |
| Dockerfile deps 階段改壞（COPY 少檔 / RUN 語法錯） | 中 | 驗收第 7 條實跑 `docker build` 直接證明；備份檔可回滾 |
| 誤動 builder 的 `npm run build`（發版路徑） | 中（觸架構師明確禁令） | 守界區明禁 + 驗收第 11 條 grep 取證原樣 |
| commit 誤帶三個既有未 commit 改動 | 中 | ⛔ 禁 `git add .` + 驗收第 9、10 條取證 |
| `git rm` 誤寫成 `--cached` 留下過期 lock 在硬碟 | 低 | 驗收第 2 條取證檔案不存在 |
| 誤打 `v*.*.*` tag 或誤 push image 觸發發版 | 低（後果高） | 硬約束明禁 + 驗證 image 用 `f4-local-verify` tag + push-gate |
