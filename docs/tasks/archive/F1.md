## 背景（規格切片）

### 實碼現況（主迴圈 2026-09-01 實查，規劃側已於同日複查檔案層一致）

`middleware.ts`（全檔 20 行，逐字）：

```ts
import { withAuth } from "next-auth/middleware"
import { NextResponse } from "next/server"

export default withAuth(
  function middleware(req) {
    // 可以額外增加更細緻的邏輯
    return NextResponse.next()
  },
  {
    callbacks: {
      authorized: ({ token }) => {
        // 只有當 token 存在且 ID 符合 ADMIN_DISCORD_ID 時才授權
        return !!token && token.sub === process.env.ADMIN_DISCORD_ID
      },
    },
  }
)

// 設定保護的路徑
export const config = { matcher: ["/admin/:path*"] }
```

`app/api/auth/[...nextauth]/route.ts` 關鍵段（`next-auth` 4.24，Discord provider，
scope 僅 `identify`）：
- `signIn` callback：`profile?.id === process.env.ADMIN_DISCORD_ID` 才 `return true`，
  其餘 `return false`。
- `session` callback：把 `token.sub` 塞進 `session.user.id`。
- `pages: { error: '/auth/error' }` ⚠️ 該頁面不存在 ⇒ 登入被拒導向 404（見裁決 4）。

`app/` 底下**確認沒有 `admin/` 目錄**；`lib/` 為空目錄。

### 兩層守門是同一條判準（鐵則 2）——但比的欄位不同

鐵則 2 明訂：`signIn` callback 與 middleware 的 `authorized` callback 是
**同一條判準的兩層**，⛔ 不得只驗一邊。
⚠️ 注意兩層比的欄位不同：middleware 比 **`token.sub`**，signIn 比 **`profile.id`**。
驗收報告必須**明確回答「這兩者實測是否為同一個值」**。
⚠️ 但⛔ 不得用 `console.log` 印出實際 ID 來比（機密不入 log）——
改用**間接證明**：若 Yu 能登入成功（⇒ `profile.id === ADMIN_DISCORD_ID` 為真）
**且**能通過 middleware 進到 `/admin` 頁（⇒ `token.sub === ADMIN_DISCORD_ID` 為真），
兩者都等於同一個環境變數 ⇒ 彼此相等，證畢。報告裡把這條推理寫出來即可，
⛔ 不需要、也不准印出 ID 值。
